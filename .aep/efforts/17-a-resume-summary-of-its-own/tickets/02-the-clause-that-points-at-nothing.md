# fix(cv): the CV summary stops naming work no output shows

## Outcome

`summary` loses the clause describing the statically typed language on a bytecode virtual machine, in both languages, and keeps everything else it says. That clause is Nova, `src/content/projects/nova-lang.yaml` is `status: in-progress`, and `isShown()` renders a project only where its status is `completed`, so the clause is the only mention of Nova anywhere in the published site and there is nothing for a reader to follow it to. The README profile block is regenerated rather than corrected, and the home page hero and both JSON documents follow the field as they already do.

## Acceptance Criteria

- [ ] Neither language's `summary` mentions a statically typed language, a bytecode virtual machine, or a language in draft (criterion 4).
- [ ] Both still name the npm package, the PL/0 compiler, and the Monkey interpreter, which are `public` and `completed` and print as entries on the CV, on the work page, and in both JSON documents (criterion 4).
- [ ] The home page hero and `basics.summary` in both `resume.json` documents carry the edited text, and `pnpm check:dist` reports `readme profile: README.md carries the profile as src/content/ states it` (criterion 5).
- [ ] `pnpm build` prints `[localized] 0 gaps`, and `pnpm check`, `pnpm check:dist`, `pnpm test`, and `pnpm test:content` pass (criterion 6).

## Relevant areas

`src/content/profile.yaml`, the `summary` field and the comment above it. `README.md`, regenerated by `pnpm readme`; `scripts/readme-profile.mjs` reads `profile.summary.en` and needs no change.

## Constraints

- **The clause comes out and nothing else does.** The third sentence keeps its other two items rather than being rewritten. The English reads as language work in Rust with two things named instead of three, and the Arabic makes the same cut.
- **`src/content/projects/nova-lang.yaml` is not edited.** Marking it `completed` is a claim about whether the work is finished and it is Saud's to make, not a side effect of editing a paragraph (`spec.md`, out of scope).
- **The README is regenerated with `pnpm readme`**, never edited by hand. The dist check compares the two and fails on a block written rather than generated.
- **The comment above the fields gains why the clause left**, so the next reader does not restore it from the work page. Ticket 01 rewrote that comment to cover both fields; this extends it rather than replacing it.

## Notes

Blocked by 01 only because both tickets edit `src/content/profile.yaml` and the comment block above its summary fields. The fields themselves are independent: this one touches `summary`, ticket 01 touches `resumeSummary`.

After this lands, Nova is named nowhere in anything the site publishes. The entry stays in the content source, and the moment its status changes it appears on the work page and the CV on its own, the way every other project gets there.
